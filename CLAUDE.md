# Agent guide — MoHeat Evo

This repo is the public GitHub Pages site for MoHeat Evo (thermal headphones) **and** the production workspace of the thermal-haptic ASMR demo series.

**Before making or updating any demo, read [`DEMO_DESIGN_GUIDE.md`](DEMO_DESIGN_GUIDE.md)** (the reusable design rules: story shape, DUAL thermal layers, voice, art, animation, layout, workflow, checklist) **and [`HANDOFF_ASMR_DEMOS.md`](HANDOFF_ASMR_DEMOS.md)**: it covers the user's standing rules, the environment, the device protocol, the shared pipeline, the status of Demo 1–4 and the next steps.

Key rules (details in the handoff):
- **Preferences + work log** (user, 2026-11-08): from every new instruction, work out the preference / habit behind it and update [`USER_PREFERENCES.md`](USER_PREFERENCES.md); at the end of every work session add an entry at the top of [`WORKLOG.md`](WORKLOG.md) (what was done, state, next steps, problems — written so another agent can pick it up). Read both before starting.
- Talk to the user in **Chinese**.
- Subtitles: the viewer picks **English (default) / 日本語 / 中文**, one language at a time, same size (user, 2026-11-08); answer buttons / prompts switch too, and voice answers are judged in that language (close in meaning passes). All through `demos/shared/subs.js` + each demo's `l10n.js` (DEMO_DESIGN_GUIDE §2.2). Story text is still written in Japanese + English; Chinese (and the cover texts) live in `l10n.js`.
- **Seedance only when the user asks**: for Demo 1–3 and Demo 9 the browser-rendered MP4 is the final film. For Demo 4 (Seasons Express) the user asked (2026-11-07) for Seedance prompts (`demos/all-ages/Demo04_SeasonsExpress/project/prompts_seedance.md`); the browser MP4 stays the current film until the clips arrive.
- **Voices: ElevenLabs by default for everything** (user, 2026-11-08), already set up; all earlier demos have been re-voiced with it too. Follow the handoff §4 "配音标准：ElevenLabs" (template code, settings, tag conventions, audition flow) instead of re-researching.
- **Images: Seedance API first, then the OpenAI API, then the Seedance website** (user, 2026-11-08, latest). ① Seedance API (`~/.seedance_key`, the demo's `scripts/seedance.py`); ② if it cannot upload (429 / long Retry-After) or fails (401, no credits) → OpenAI API `gpt-image-2` (`~/.openai_key`; `python3 tools/openai/images.py <demo> <job…>`, prompts from `project/web_prompts.json`, reference files sent directly — no upload quota); ③ only if that fails too → the seedance2-5.com website via Chrome (`tools/seedance/web_helpers.js` + `web_take.py`; the user must be signed in). Video: Seedance (API, else website). Credit / token checklist: `DEMO_DESIGN_GUIDE.md` §5.3 and §6.1.
- **Standard production = Gaku / Demo24_GakuCamp (layered, ex-Demo27)** (user, 2026-11-08): every new demo's picture is made in layers — one empty background plate per place, plain-background poses (pose changes that keep the face = edits of the base, sharing its face patches), Seedance-drawn mouth-open / eyes-closed variants → `python3 tools/art/build_stage.py <demo>` (Pillow + numpy) → `media/layers.js` + `demos/shared/layers.js` animate the stills (parallax, fire, breathing, mouth fade, blinks). Seedance video only for dynamic CGs that pass §6.3. Steps: `DEMO_DESIGN_GUIDE.md` §6 "标准制作流程".
- **One engine, no demo-to-demo dependencies** (user, 2026-11-08: "demo 都要起源一个规范模版类似引擎…demo 之间不应该存在依附性" / "同一个类别可以共享一个依赖"): a demo loads only from its own folder, `demos/shared/**` and its own category kit `demos/<category>/_kit/**` — never from another demo's folder or another category's kit, no `<base href>` to another folder, no symlink out of the folder; demo-to-demo navigation only via `nav.js` data. Something a second demo in the category needs moves into the kit. Earlier demos may be edited for decoupling / migration, verified with `tools/qa/trace_demo.js` (identical before / after) and `python3 tools/qa/check_deps.py --fail`. Plan and status: `docs/engine/`; rules: DEMO_DESIGN_GUIDE §12.1. A **remake replaces its original** (user, 2026-11-08) — build it in a staging folder, then `python3 tools/web/merge_remake.py <original> <staging>` merges it into the original folder (same URL) and backs the old version up outside the repo (`~/Desktop/MoHeat Evo 备份/<category>/<folder>_<time>/`).
- **Commit and push every change to `origin main`.** Large media stay out of git. **Hard rule — several sessions share one working tree and one index** (bit us 3× on 2026-11-08: foreign staged files swept into a commit, a WORKLOG rollback, the guide truncated): commit **only your own paths, yourself** — `git commit -- <your paths>` when the files are wholly yours, or a temp index (`GIT_INDEX_FILE=$(git rev-parse --git-dir)/index.mine git read-tree HEAD`, add your HEAD-based blobs, `write-tree` / `commit-tree` / `update-ref HEAD <new> <old>`) for shared files that also hold others' uncommitted edits — never a bare `git commit` (it takes whatever others staged); **never move HEAD backwards** (no `git reset` / rebase / amend / force on the shared main — fix a mistake with a new forward commit); never truncate-then-write a shared doc (write a temp file + `os.replace` / `mv`); re-read a file right before editing it; check `git show --stat HEAD` after every commit. Guide §6 制作流程 v2, G7.
- **Easy to change, maintain and use** (user, 2026-11-08; DEMO_DESIGN_GUIDE §14): shared code first (`demos/shared/`), content as data (`lines.js`, `l10n.js`, `LANGS`, `DEMOS`, `GATES`), repeated jobs as `tools/` scripts (`tools/web/bump.py` for `?v=` numbers, `tools/l10n/check_missing.js`), read-before-write, commit only your own changes and push right after staging. UI standard for every demo: §7.3.
- **ONE interface, identical in every demo — UI v2** (user, 2026-11-08; DEMO_DESIGN_GUIDE §7.3 "UI v2"): the cover is a finished image rendered by `tools/web/covers.py` from the demo's `cover.json` + `media/cover/art.webp` (never drawn per demo), with live Start / mode / options / language on it; one always-visible control bar (▶ · chapters · mode · 🔊 · 🌡 · ⚙ · ⛶) and the ⚙ panel come from `demos/shared/ui2.js` + `ui2.css` via `shell.js` (switch `MoHeatShell.UI_V2`). A demo writes NO UI code and no `.u2` rules — only content, `cover.json` and chapters (`#steps` or `MoHeatShell.chapters`). Gate: `check_demo.py` G7 **ui** (`tools/web/check_ui.js`: every element identical to the reference demo in 5 states × 2 sizes; FAIL on any difference).
- **Keep the repo tidy** (user, 2026-11-08): new files follow the folder layout in `DEMO_DESIGN_GUIDE.md` §12; after each finished demo run `python3 tools/cleanup/audit.py` and, with the user's OK, move unneeded resources to the Trash (`--trash`).
- **After any problem, write a lesson** (user, 2026-11-08): add it to `DEMO_DESIGN_GUIDE.md` §11.1 出错记录 (symptom → cause → what to do next time; merge with an existing entry instead of repeating it), turn it into a tool / automatic check when possible, and tell the user. Read §11.1 before starting similar work.
- **QA gates: 制作流程 v2** (user, 2026-11-08: keep iterating the workflow from lessons; every lesson must become a check): follow the gated steps G0–G8 in `DEMO_DESIGN_GUIDE.md` §6 "制作流程 v2"; one QA entry point `python3 tools/qa/check_demo.py <demo>` (`--quick` no browser, `--full` before release / merge, `--checklist` writes `project/CHECKLIST.md`) must show 0 FAIL before a demo goes live; `merge_remake.py` refuses to merge when it fails. New lessons → a new check in it (or a CHECKLIST item).
- Thermal output per ear: the old commands (`LC50 RH0`) are one mode per ear (cool or heat), and every old thermal CSV must keep 0 same-ear conflicts. Since 2026-11-08 the firmware (`arduino/`, local only) also takes `DUAL LC.. LH.. RC.. RH..`: cool and heat independent on the same ear. The user prefers new demos to use it: a voice close to your ear warms it with its loudness, and ambient warm / cool shows the surroundings.
- **Every demo page fits exactly one screen** (no page scroll at common desktop sizes, and on phones / tablets in portrait and landscape with the player as large as possible — DEMO_DESIGN_GUIDE §7.1) with a layout as consistent as possible across demos; thermal mappings must be physically plausible (no warmth just because a character eats something spicy), and a human voice is always warm (strongest at the ear, milder with distance) unless the character has a special setting such as a snow spirit. Applies to all new demos (user, 2026-11-08).
- **Voice input judging** (user, 2026-11-08): every demo with dialogue lets the player answer by voice, and what they say is judged (not just the mic level). Use `demos/shared/voice.js` (auto-handles `.ch` / `.act-btn` / `.chip-c` / `#micGate` buttons; `interact.js` uses its API). Rules: `DEMO_DESIGN_GUIDE.md` §2.1.
- **Strict layers** (user, 2026-11-08): background, characters, effects and props are made and animated separately and stacked in the page, so Seedance credits go only to the layer that really needs it (faces / talking via LivePortrait, parallax via depth maps, effects in code: `tools/animate/`). Rules: `DEMO_DESIGN_GUIDE.md` §6.2.
- **Seedance only for what really needs it** (user, 2026-11-08): stills + expression variants + staging first (visual-novel / otome / Live2D practice); a Seedance video only when the motion itself is the highlight, can't be told with stills + staging, and is tied to a thermal or interaction moment. Talk loops, idle loops and per-cut transitions are no longer default (LivePortrait / code instead). Budget and checklist: `DEMO_DESIGN_GUIDE.md` §6.3. Clips that pass still follow handoff §4b (2.5 Lite 1080p, first & last frame = stills, snap to the still).
