# Agent guide — MoHeat Evo

This repo is the public GitHub Pages site for MoHeat Evo (thermal headphones) **and** the production workspace of the thermal-haptic ASMR demo series.

**Before making or updating any demo, read [`DEMO_DESIGN_GUIDE.md`](DEMO_DESIGN_GUIDE.md)** (the reusable design rules: story shape, DUAL thermal layers, voice, art, animation, layout, workflow, checklist) **and [`HANDOFF_ASMR_DEMOS.md`](HANDOFF_ASMR_DEMOS.md)**: it covers the user's standing rules, the environment, the device protocol, the shared pipeline, the status of Demo 1–4 and the next steps.

Key rules (details in the handoff):
- Talk to the user in **Chinese**.
- Subtitles: the viewer picks **English (default) / 日本語 / 中文**, one language at a time, same size (user, 2026-11-08); answer buttons / prompts switch too, and voice answers are judged in that language (close in meaning passes). All through `demos/shared/subs.js` + each demo's `l10n.js` (DEMO_DESIGN_GUIDE §2.2). Story text is still written in Japanese + English; Chinese (and the cover texts) live in `l10n.js`.
- **Seedance only when the user asks**: for Demo 1–3 and Demo 9 the browser-rendered MP4 is the final film. For Demo 4 (Seasons Express) the user asked (2026-11-07) for Seedance prompts (`demos/all-ages/Demo04_SeasonsExpress/project/prompts_seedance.md`); the browser MP4 stays the current film until the clips arrive.
- **Voices: ElevenLabs by default for everything** (user, 2026-11-08), already set up; all earlier demos have been re-voiced with it too. Follow the handoff §4 "配音标准：ElevenLabs" (template code, settings, tag conventions, audition flow) instead of re-researching.
- **Images: OpenAI API first** (`gpt-image-2`, key `~/.openai_key`, `/v1/images/edits` with the reference file — no upload quota; template `demos/for-men/Demo31_SummerRooftop/scripts/gpt_image.py`); if it is unavailable (no credits / 401 / error) → **Seedance API** (`~/.seedance_key`); if that is blocked (upload 429 / long Retry-After, 401) → the **seedance2-5.com website** via Chrome (user, 2026-11-08). Same prompts everywhere. **Video stays Seedance** (API first, then website). Details and the credit / token-saving checklist for video: `DEMO_DESIGN_GUIDE.md` §5.3 and §6.1.
- **Standard production = Gaku / Demo27_GakuFireside** (user, 2026-11-08): every new demo's picture is made in layers — one empty background plate per place, plain-background poses (pose changes that keep the face = edits of the base, sharing its face patches), Seedance-drawn mouth-open / eyes-closed variants → `python3 tools/art/build_stage.py <demo>` (Pillow + numpy) → `media/layers.js` + `demos/shared/layers.js` animate the stills (parallax, fire, breathing, mouth fade, blinks). Seedance video only for dynamic CGs that pass §6.3. Steps: `DEMO_DESIGN_GUIDE.md` §6 "标准制作流程".
- **Never modify earlier demos**: reuse art by symlink and code by import-by-path.
- **Commit and push every change to `origin main`.** Large media stay out of git.
- **Easy to change, maintain and use** (user, 2026-11-08; DEMO_DESIGN_GUIDE §14): shared code first (`demos/shared/`), content as data (`lines.js`, `l10n.js`, `LANGS`, `DEMOS`, `GATES`), repeated jobs as `tools/` scripts (`tools/web/bump.py` for `?v=` numbers, `tools/l10n/check_missing.js`), read-before-write, commit only your own changes and push right after staging. UI standard for every demo: §7.3.
- **Keep the repo tidy** (user, 2026-11-08): new files follow the folder layout in `DEMO_DESIGN_GUIDE.md` §12; after each finished demo run `python3 tools/cleanup/audit.py` and, with the user's OK, move unneeded resources to the Trash (`--trash`).
- Thermal output per ear: the old commands (`LC50 RH0`) are one mode per ear (cool or heat), and every old thermal CSV must keep 0 same-ear conflicts. Since 2026-11-08 the firmware (`arduino/`, local only) also takes `DUAL LC.. LH.. RC.. RH..`: cool and heat independent on the same ear. The user prefers new demos to use it: a voice close to your ear warms it with its loudness, and ambient warm / cool shows the surroundings.
- **Every demo page fits exactly one screen** (no page scroll at common desktop sizes, and on phones / tablets in portrait and landscape with the player as large as possible — DEMO_DESIGN_GUIDE §7.1) with a layout as consistent as possible across demos; thermal mappings must be physically plausible (no warmth just because a character eats something spicy), and a human voice is always warm (strongest at the ear, milder with distance) unless the character has a special setting such as a snow spirit. Applies to all new demos (user, 2026-11-08).
- **Voice input judging** (user, 2026-11-08): every demo with dialogue lets the player answer by voice, and what they say is judged (not just the mic level). Use `demos/shared/voice.js` (auto-handles `.ch` / `.act-btn` / `.chip-c` / `#micGate` buttons; `interact.js` uses its API). Rules: `DEMO_DESIGN_GUIDE.md` §2.1.
- **Strict layers** (user, 2026-11-08): background, characters, effects and props are made and animated separately and stacked in the page, so Seedance credits go only to the layer that really needs it (faces / talking via LivePortrait, parallax via depth maps, effects in code: `tools/animate/`). Rules: `DEMO_DESIGN_GUIDE.md` §6.2.
- **Seedance only for what really needs it** (user, 2026-11-08): stills + expression variants + staging first (visual-novel / otome / Live2D practice); a Seedance video only when the motion itself is the highlight, can't be told with stills + staging, and is tied to a thermal or interaction moment. Talk loops, idle loops and per-cut transitions are no longer default (LivePortrait / code instead). Budget and checklist: `DEMO_DESIGN_GUIDE.md` §6.3. Clips that pass still follow handoff §4b (2.5 Lite 1080p, first & last frame = stills, snap to the still).
