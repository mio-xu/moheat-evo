# 展示模式（Kiosk）· 全部要求

用户 2026-11-08 在对话中提出、认可的全部要求，供实现、测试和以后修改时对照。
实现说明另见 `docs/kiosk.md`（工作人员设置说明）和 `docs/kiosk_staff_card.md`（A4 速查卡）。

## 1. 为什么要有
展会、店面用同一台电脑轮流给不同的人体验。每位访客都是第一次用，都需要设备引导。普通网页的引导只出现一次，所以要有专门的展示模式（TASKS #54，优先做）。

## 2. 每位访客的流程
1. **欢迎画面**：大按钮、三语（英文默认 / 日本語 / 中文，留好韩语位置），选语言。
2. **2 秒片头**：MoHeat Evo 标志，两只耳朵感受一次冷 → 暖扫过，同时确认设备连上。
3. **30 秒设备引导**（可跳过）：
   - 戴好耳机（耳罩标出左 / 右）；
   - **调音量**；
   - 左耳暖 → 右耳凉 → 冷热快速切换 → 同一只耳朵冷热同时；
   - 选择舒服的强度（强一点 / 弱一点）。
   - **戴降噪入耳式耳机可能听不到语音说明，所以整个引导不靠声音也能看懂**：每一步都有大图标或短动画，加一行简短文字和进度点。
4. **选 Demo → 体验**：默认纯享模式，可以切换成互动模式；可以选 60–90 秒的**展会精华版**。
5. **用户体验卡**（见第 4 节）。
6. **自动重置**：体验结束，或约 60 秒没人操作，就回到欢迎画面，清空上一位的设置（语言、模式、强度回到温和默认），冷热输出停止。

## 3. 页面上随时可用
- **大的音量滑块**：访客自己随时调，按钮 ≥ 44 px。
- 冷热快捷开关、暂停、结束。

## 4. 用户体验卡（简单好填，不能引起反感）
- 一屏一题、大按钮、点了自动下一题，不用打字；轻提示 ●○○○，开头一句话：「点 4 下就好，谢谢！」。
- 每屏都有「跳过」和「全部跳过」；约 15 秒无操作自动关闭，算作跳过；不标红色必填、不弹窗、不像推销；整张卡约 10 秒答完。
- 题目（按顺序）：
  1. 打分 1–5 星：冷热体验怎么样
  2. 作为商品想买吗：有 / 也许 / 没有
  3. 只在选「有 / 也许」时出现：如果有卖，你觉得多少钱合理？4–5 个价格区间按钮（工作人员可设，币种默认按显示语言）
  4. 你会在什么场景用它（最多选 2 个）：ASMR / 助眠放松 · 恋爱向 / 角色声音内容 · 游戏和 VR · 疗愈陪伴（家人、宠物）· 品牌 / 活动体验 · 旅行观光 · 专注 / 睡眠辅助 · 其他
  - 选填：最喜欢的冷热瞬间；一句话留言，藏在小链接「写点什么」后面
- 结尾：2 秒以内的感谢画面，以及一个扫码带走的体验小结（体验了什么 + 官网链接，不含个人信息）。
- 可选：「想收到产品消息？」二维码，指向外部表单，由访客自己决定；网站本身不收集个人信息。

## 5. 统计（只存本机，匿名）
- 每天的访客数；**每个 Demo 被体验的次数**（开始 / 看完）；纯享 / 互动；平均分；最喜欢的瞬间；留言。
- 问卷统计：购买意愿、价位、场景的分布，按 Demo、按天分开；交叉表：购买意愿 × 价位、场景 × 购买意愿。
- 工作人员面板里显示「今天 / 累计 体验最多的 Demo」，可以导出 CSV / JSON；数据不发送到任何地方。

## 6. 工作人员
- 进入方式：展示网址 `?kiosk=1`（对这台浏览器保持有效），或在设置里打开。
- 隐藏面板：角落连按 5 次加一个简短的 PIN。可设置默认语言、强度上限、空闲重置时间、开放哪些 Demo、价格区间和币种；可以导出统计、退出展示模式。
- 文档：一页设置说明（`docs/kiosk.md`），加 A4 速查卡（开机步骤、网址、常见问题：没声音 / 不冷不热 / 画面卡住、怎么进面板；电脑不要睡眠）。

## 7. 现场环境和安全
- 空闲时轮播各 Demo 的精彩片段，冷热关闭。
- 第二块屏 / 观众视图：同步画面，并显示大的冷热可视化（两只耳朵变色、雪花 / 热气）。
- 断网也能用：提前缓存全部 Demo（PWA / service worker）。
- 每位新访客都从温和强度开始；长时间连续输出时自动安排间歇；设备断开或没电时，屏幕上大字提示。

## 8. 验收
- 以第一次来的访客身份，在笔记本电脑和平板上完整走几遍流程：引导 → Demo → 体验卡 → 重置 → 轮播 → 工作人员面板 → 导出。
- 关掉声音也能看懂引导；体验卡 10 秒内能答完。

## 9. 补充（2026-11-08，这次展示只有一台电脑）
- 只按**一台电脑、一副耳机**设计，不做多设备并行。人流只能靠一台机器消化，所以展示模式默认用**展会精华版（60–90 秒）**，工作人员可以在面板里改成完整版。
- 欢迎画面直接推荐冷热最强的 **3 个 Demo**（按推荐度自动选），每个配一句话简介，其余的放在「更多」里。
- **排队时预选**（用户 2026-11-08 确认，普通项目，不用服务器）：排队处的二维码 → 手机页（静态、三语）列出展示机开放的 Demo，每个带一句简介和冷热看点；点一个就显示大卡片「你的号码：7 · 标题」。展示机欢迎画面每个 Demo 都标同样的号码，访客（或工作人员）直接点号码。两边号码一致，号码表跟着工作人员面板的「开放的 Demo」走（二维码里带着这张表）。只在展示机上计数。
- **二维码要出现在屏幕上**，不只是打印的牌子：轮播画面、欢迎画面角落（「排队时扫码先选」，当前语言）、排队屏 / 观众屏（1–2 m 外能扫）；另有可打印的 A4 海报页。二维码指向 GitHub Pages 上的手机选择页，网址可在工作人员面板里改（自定义域名时）。
- **两块屏幕、一台电脑**：屏幕 1 给体验者（欢迎、引导、Demo、体验卡，只有角落小二维码）；屏幕 2 面向排队的人（工作人员面板打开第二个窗口，拖到第二块显示器全屏，同一台电脑上 BroadcastChannel / localStorage 同步）：大二维码「排队时扫码选 Demo」、体验者画面的镜像 + 大的冷热可视化（两只耳朵变色、雪花 / 热气）、正在体验的 Demo 和号码、推荐的 3 个；空闲时轮播。字要大，2–3 m 外看得清。
- **默认模式是互动**（用户 2026-11-08，所有地方）：展示模式里每位新访客重置为互动（纯享是可选项）；轮播仍然无输入、无冷热；点按永远可用（访客可能不想说话）。
- **和统一外壳一致**：外壳改成统一封面 + 底部控制条（▶/⏸ · 章节 · 模式（播放中也能切换）· 音量 · 🌡 · ⚙ · ⛶）后，展示模式用同一条控制条和音量控件（`MoHeatShell.setVolume` 存在时展示模式不再自己加音量滑块）。
- **每日报表**：每天结束时，工作人员面板一键生成当天小结（人数、最受欢迎的 Demo、购买意愿 / 价位 / 场景分布），可以导出。
- **卫生提示**：欢迎画面可以加「耳罩已消毒 / 可用一次性耳罩套」的小标识，由工作人员开关。
- **问卷结果用来优化 Demo**：平均分低的 Demo、最受欢迎的冷热瞬间，汇总后作为全 Demo 扫描时的改进优先级。

## 10. 用户试用后的修改（2026-11-08）
- 冷、热强度**分开自动校准**：暖、凉各一步，从很弱慢慢加强（约 6–8 秒到工作人员上限），屏幕大字提示「**快要不舒服时点一下**」；点的那一刻立刻停止，记为这位访客的个人上限，实际使用其约 80 % 当作 100 %；没人点就停在工作人员上限；任何点击 / 按键立即停止。工作人员面板保留暖、凉各自的上限（工作人员也可以用同样的自动校准给自己测一次来设上限）；各访客的个人上限匿名计入统计。
- 问卷不能跳太快：选中后高亮约 0.8 秒再进下一题；每题至少停留约 1.5 秒，防止误触；可以返回上一题；15 秒无操作仍然自动关闭。
- 第二块屏幕（排队屏）主要**循环播放宣传视频**，画面上一直叠着二维码。宣传视频等 Demo 都做好后再统一制作（TASKS #50 ③）；在那之前，排队屏先显示现在的轮播 + 冷热可视化。工作人员面板可以选：宣传视频 / 实时画面 / 每 N 分钟轮换，以及视频文件、二维码大小和位置。

## 11. 进入时的引导流程（用户 2026-11-08 定稿，取代 §2 第 3 步）
每一步都有视觉引导：大图示、对应那只耳朵亮起（暖橙 / 冷蓝）、步骤进度条、一个大按钮、所选语言的短句；不靠听说明也能看懂。全部用 ASMR 音频。
1. 戴上降噪入耳式耳机（标出左 / 右）。
2. 测左右方向和音量：左耳一段 ASMR 声，问「是左边吗？」（是 / 不是→提示把耳机转过来再测），再测右耳；然后边播放轻柔 ASMR 边调音量到「舒服又清楚」。
3. 暖：左耳慢慢变热，「快要不舒服时按停止」，大大的「停止」按钮，记为个人暖上限（使用约 80 %）。
4. 凉：同样方式。
5. 暖的试听：焰（狐火精灵）凑到耳边说话的 ASMR，暖意跟着她的声音；问「自然吗？」三个选项：太弱 / 刚好 / 太强（暖强度 ±15 %，可重听一次）。
6. 凉的试听：小雪（雪之精灵，气息是凉的）凑到耳边说话；同样三个选项调凉强度。
7. 冷热同时输出不用测。
- 「跳过引导」照常保留；校准结果和"自然吗"的回答匿名计入统计。
- **补充（2026-11-08）**：先戴**降噪入耳式耳机**做左右 + 音量测试 → 画面提示「声音没问题的话，请告诉工作人员」（工作人员点「继续」）→ 工作人员给访客戴上 **MoHeat Evo 冷热耳机** → 左暖 / 右暖 / 左凉 / 右凉 各约 2 秒的输出确认 → 提示「两边冷热都感觉到了的话，请告诉工作人员」（工作人员点「继续」）→ 进入校准（暖停止 / 凉停止）和焰 / 小雪试听。
- 引导里所有语音都用访客选的语言（英 / 日 / 中），并且是**从左边慢慢移动、凑到耳边说话**的 ASMR 立体声效果。
- **体验结束（2026-11-08）**：没人排队时，访客可以继续体验别的 Demo（不用重新引导和校准）；有人排队时必须结束。排队状态由工作人员用一个不显眼的开关设置（角落长按 / 键盘 Q，不用 PIN，展会默认「有人排队」），可选每人最长时间 / 最多几个 Demo。结束顺序：冷热先停止 →「请先摘下 MoHeat Evo」（工作人员点继续）→「再摘下降噪入耳式耳机」→ 体验卡问卷 → 感谢 + 带走二维码 → 重置给下一位。
- 引导里的每段测试语音都在 **15 秒以内**（左右测试每边约 3–4 秒，音量循环约 6–8 秒，焰 / 小雪试听各约 8–12 秒，校准升温 / 降温约 6–8 秒）；整个引导连同两次工作人员确认，目标约 2 分钟以内。
- **硬件说明（2026-11-08 更正）**：降噪的是**入耳式小耳机**（出声音），MoHeat Evo 是戴在外面的**大耳机**（出冷热）。先戴入耳式耳机，再由工作人员戴上 MoHeat Evo；摘下时先摘 MoHeat Evo，再取下入耳式耳机。所有文字和图示按这个写。
- ASMR 测试音频的音量变化要更大：远处明显轻，到耳边明显响、贴近（舒服、不破音），冷热跟同一条音量曲线。
- **更正（2026-11-08）**：每位访客都可以**完整体验完一个 Demo**。展示模式默认放完整版；展会精华版（60–90 秒）只作为工作人员面板里的可选项，默认关闭。

## 12. 现场标识：可以触摸 / 请勿触摸 / 可以拍照（用户 2026-11-09）
用户原话：「demo的时候，给体验者和其他人的提示需要加上，有人的时候接触可，无人的时候不可接触，拍照可的表示标识」。
- **三种标识**：工作人员在场 →「欢迎体验（可以触摸）」；无人值守 →「请勿触摸 · 工作人员马上回来」；一直显示 →「可以拍照」（场地禁止拍照时，工作人员改成「请勿拍照」，相机加斜杠；也可隐藏）。
- **图标按标准样式**：绿色圆底白色图案 = 可以（手 / 相机）；白底红圈 + 红色斜杠 + 黑色图案 = 禁止。图标 + 一行短字，不靠文字也能懂。
- **出现的位置**（同一个组件 `kiosk/signs.js` + `signs.css`）：
  - 访客屏欢迎画面：角落小标识（访客选的语言，只有图标 + 标题，不挡任何按钮；引导、Demo、体验卡里不显示）；竖屏 / 窄屏只显示图标；
  - 空闲轮播：大一点的标识，英文 + 日文同时显示（给路过的人看）；
  - 排队屏：实时画面里放在二维码下面，宣传视频模式放在二维码角标里；英文 + 日文同时显示，2–3 m 外看得清；无人值守时变成红框「请勿触摸」；
  - 可打印的立牌 `kiosk/sign.html`（面板「Print signs」）：A4 / A5 竖版，两页（工作人员在场 / 无人值守），英文 + 日文 + 中文，底部是拍照标识。
- **工作人员开关「在场 / 无人」**（和排队开关同样的做法，不用 PIN）：左下角**第二个小圆点**（绿 = 在场，红 = 无人）长按约 1 秒，或键盘 **S**；面板里也有开关。默认「在场」。
  - 无人值守时：访客屏整屏显示「请勿触摸 · 工作人员马上回来」（全部语言），底下是轮播；冷热输出停止；点按和按键全部无效，只有工作人员的方式能用（长按小圆点 / S 键、左上角 5 次 + PIN）。切回「在场」→ 回到欢迎画面迎接下一位。
  - 通过设置（localStorage）+ BroadcastChannel 同步到排队屏。
  - 在场 / 无人的时段按天记在本机（`moheat.kiosk.presence`，匿名）：面板统计显示「staffed / unattended（时:分）」，Export CSV 末尾附时段表，Export JSON 附 `presence`。
- **面板设置（Signs）**：触摸标识开 / 关；拍照标识「可以拍照 / 请勿拍照 / 隐藏」；分别在欢迎画面、空闲轮播、排队屏显示与否；访客屏角标的位置（四个角）。
- **语言**：英文（默认）/ 日本語 / 中文，留好韩语位置（文字都在 `signs.js` 的 `TX` 里，不写死在页面上）。
- **限制**：Demo 页面（`demos/**`）上没有这个开关和整屏提示——工作人员离开前，先让访客结束体验或等回到欢迎画面再切换。
